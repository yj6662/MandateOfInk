# CLAUDE.md — 오행부(五行符) 개발 지침

이 파일은 Claude Code가 오행부 프로젝트에서 작업할 때 따르는 지침이다. 매 세션 자동으로 읽힌다.
**세션 시작 시 이 파일 다음으로 `PROGRESS.md`를 반드시 읽고, 작업 단위가 끝날 때마다 `PROGRESS.md`를 갱신한다.**

## 프로젝트 한 줄
오행부(五行符): Unity 6 / URP로 만드는 **1인칭 한글 작도(作圖) 액션 어드벤처**(소울라이크). 마석으로 굴러가는 대체역사 조선이 배경. PC(Steam) 유료 싱글플레이. 1인 개발(팀 미적 · 微跡 · 한예준) + AI 보조 파이프라인.

## 이 저장소에서 너(Claude)의 역할
너는 **배관(plumbing)** 담당이다 — 로직·자동화·반복 작업에 강하고, 아트·미적 판단은 사람이 한다.

**네가 하는 일**
- C# 게임플레이 로직: 한글 작도 입력·인식($1류 제스처 인식기), 진(陣) 효과 시스템, 전투/적 AI, VFX 스폰·풀링, 절차적 모션(C# + IK), 씬 와이어링, 데이터 주도 DTO/ScriptableObject.
- DI·이벤트 채널·상태머신 아키텍처(아래 참조)를 따른 시스템 구현·리팩터·디버그·테스트.
- Odin 기반 데이터 에디터 툴(OdinMenuEditorWindow 등) 제작 — 단, 에디터 계층 한정.
- Blender MCP / Unity MCP 절차 스크립트(방사 배열·불리언·정렬·씬그래프 점검·익스포트 등).

**네가 임의로 결정하지 않는 일 (사람 영역 — 막히면 물어볼 것)**
- 아트디렉션·룩·"먹으로 보이나" 판정, 손맛·전투 가독성·시간 개연성 튜닝.
- 셰이더 그래프 노드 저작(셀/먹 룩 셰이더는 에셋으로 충당). 셰이더가 필요하면 직접 만들지 말고 어떤 에셋/접근을 쓸지 물어볼 것.
- 보스·캐릭터의 유기적 조형, 표현적 키프레임 애니메이션(외주/사람).
- 기획 미결 사항(아래 「미결 사항」 목록) — [제안]으로만 다루고 확정 처리하지 않는다.

## 소통 규칙
- **한국어로 답한다**(기술 용어는 영어 병기 가능). 해요체, 산문 위주, 불릿·볼드 남발 금지.
- 코드 설명은 **입문자 눈높이로 단계별·친절하게** — "무엇을 / 왜"를 같이 짚는다. 한예준은 CS 비전공 1인 개발자다.
- 코드 수정은 신중히. 바꾸기 전에 **무엇을 왜 바꾸는지** 먼저 말한다. 대량·위험 변경은 계획부터 공유한다.
- 문서·캔버스에 **이모지 아이콘 금지**.
- 문서 체계: **사람용(공유·인쇄) 문서는 PDF 단독 전달**(WeasyPrint, ink/paper 팔레트 · INK #2A2622 / PAPER #F7F1E4 / ACCENT #8A5A33, A4). **Claude Code·개발용 문서는 Markdown(.md) + CSV**로 리포에 둔다.

## 아키텍처 — DI · 이벤트 채널 · 데이터 주도 (절대 규칙)
- **의존성 주입(DI)**: VContainer로 시스템 의존성을 주입한다. 전역 싱글턴 매니저 구조(구 "The Last One" CoreManager)는 **폐기했다** — 새 시스템은 싱글턴에 의존하지 않는다. 기존 문서(게임기획서 v1.4 §8 등)에 남은 CoreManager 언급은 구버전 잔재이므로 무시한다.
- **ScriptableObject 이벤트 채널**: 시스템 간 통신은 SO 이벤트 채널로 느슨하게 결합한다(직접 참조·강결합 지양).
- **상태머신**: 작도-시점 전환, 전투 모드(탑승↔도보), 적 AI는 명시적 상태머신으로 다룬다.
- **Assembly Definitions**: 도메인별로 asmdef를 나눠 모듈화한다(예: Core / Spellcraft / Combat / Data / Presentation / EditorTools). **런타임 코어는 Odin·에디터 의존성에서 독립** — 런타임 코어 asmdef는 Odin을 참조하지 않는다.
- **비동기**: UniTask로 처리한다.
- **데이터 주도**: 진(도면)·속성·적·보상은 SO/DTO로 다룬다. 수치·밸런스 하드코딩 금지 — [가정] 표시 플레이스홀더 수치 포함 전부 데이터로 뺀다.
- **Odin 데이터 계층 패턴**: 데이터 SO는 SerializedScriptableObject 상속, 5×5 상극 테이블은 Dictionary + Odin 직렬화, 효과 파라미터는 추상 기반 클래스 다형성, 데이터 편집 창은 OdinMenuEditorWindow. Odin은 Personal 라이선스(Validator 스킵), 에디터/인스펙터·데이터 SO 계층에만 사용.

## 핵심 시스템 — 한글 작도 (절대 규칙)
작도는 추상 마법진이 아니라 **한글**이다. 한 글자 = 하나의 진. 추상 도형으로 되돌리지 마라.
- **초성(자음) = 오행 속성**: 아음 ㄱㅋ=목 / 설음 ㄴㄷㅌㄹ=화 / 순음 ㅁㅂㅍ=토 / 치음 ㅅㅈㅊ=금 / 후음 ㅇㅎ=수.
- **중성(모음) = 음양 × 천지인**: 음양 — 양성(ㅏㅗㅑㅛ)=양(발산·공세) / 음성(ㅓㅜㅕㅠ)=음(수렴·방어/설치). 천지인 — ㅏㅓ=단일 대상 / ㅗㅜ=영역·여러 대상(바닥 장판 아님). 강도축(ㅑㅕㅛㅠ=강화판)은 후속, ㅣㅡ 특수 중성은 후순위.
- **종성(받침) = 거동(속성별 1개)**: ㄱ(목)=속박 / ㄴ(화)=지속 / ㅁ(토)=격발(상합 설치) / ㅅ(금)=관통 / ㅇ(수)=연쇄. (받침 없음 = 빠른 기본형)
- 예: 「다」(ㄷ화+ㅏ)=단일 화염 타격, 「우」(ㅇ수+ㅜ)=광역 수막 방어, 「검」(ㄱ목+ㅓ+ㅁ받침)=덩굴 표식 상합 설치.
- 입력 파이프라인: 마우스 궤적 수집 → 자모 인식($1 Unistroke Recognizer C# 포트 후보) → 음양/획 품질 평가 → 진 발동. 판정 3단계(자모 인식 → 음양 → 획 품질).
- 폴백: 임계 미달 시 가장 가까운 자모로 약발동(완전 불발 금지). 상세 규칙은 「작도 시스템 설계안 v2.0」 참조.
- **자모 획 인식은 이 프로젝트 최고 위험 가정**이다. 본 프로젝트에 붙이기 전 스파이크 프로젝트로 선행 검증하는 것을 우선한다.

## 재화 (절대 규칙)
- **화폐 = 조선통보(朝鮮通寶)**. 상점 구매·사망 시 드롭/회수에 사용.
- **마석(魔石)은 화폐가 아니다** — 작도 연료(먹)이자 강화/해금 재료. 전투·탐험으로 직접 수급.
- 이 둘을 절대 합치거나, 마석을 통화로 쓰지 말 것.

## 분기 · 스토리 데이터 (절대 규칙)
- 분기는 **가중치 점수 방식이 아니라 순수 플래그**(필수/금지 집합)로 판정한다. 예외적 카운터는 라인 내부 2종(왕소 신뢰·무학 조우)뿐.
- 엔딩 4종: 조선 충신(기본/fallback) · 고려 부흥 · 은둔/태극(진엔딩) · 제3세력. 태극은 중립 게이트 — 타 진영 commitment 플래그 부재 시에만 개방.
- 원본 데이터는 `오행부_분기플래그원장_v0_3.csv`(action_id·세팅 플래그·선행조건·상호배타그룹). 코드·툴에서 분기 데이터를 다룰 때 이 CSV를 단일 진실로 삼는다. 사양은 「분기 시스템 사양 v0.3」.

## UI · HUD 정책
- **최소 HUD** — 허용: 락온 레티클, HP, 잉크(먹) 미터, 부적 수, 상호작용 프롬프트, 화물 상태. 금지: 미니맵, 퀘스트 마커, 대미지 수치, 일반 적 HP 바.
- UI는 디제틱 우선(차패 상태창, 붓·먹으로 자원 표현).

## 기술 스택 · 컨벤션
- Unity 6 · URP · C#. 입력은 마우스+키보드(작도-시점 혼합형) 우선.
- DI = VContainer, 비동기 = UniTask, 모듈 = Assembly Definitions, 에디터 확장 = Odin(계층 한정).
- **프로젝트 초기화 순서(준수)**: 프로젝트 생성 + asmdef 경계 확립 → 그 다음 Odin Inspector 설치. 초기 필수 세팅: Asset Serialization = Force Text, Version Control = Visible Meta Files, Color Space = Linear, URP 프리셋.
- 프로토타이핑: ProBuilder + Kenney 프로토타입 텍스처.
- 비주얼: 셀/툰 셰이딩 + 풀스크린 먹 포스트(외곽선·한지 그레인·세피아 LUT). 셰이더는 에셋 후보(Flat Kit, Dissolvable Ink Painting Effects, Snapshot Shaders Pro, Outline Plus 등). URP Render Graph 호환은 에셋별 확인.
- 네이밍·폴더 구조는 확정되는 대로 `PROGRESS.md` 「프로젝트 메모」에 기록한다.

## 생성형 AI 파이프라인
- 3D = Meshy(+ Hyper3D·Hunyuan3D 후보) → Blender 조립(Claude 절차 스크립트) → Unity. 2D/UI = Recraft. 음악 = Suno.
- 상용 게임이므로 **유료 플랜 상업 이용권 확보 필수**. Suno 산출물은 저작권 보증에 법적 불확실성이 있으므로 출시 전 반드시 사람 검토(human-in-the-loop).
- 애니메이션 = Mixamo 리타깃 + 절차적(C#+IK) + Cascadeur + 외주. 기계 부품 = 리지드 페어런팅 / 유기부 스키닝 = 사람.
- 한글 폰트는 눈누(noonnu.cc)에서 상업 임베딩 가능 여부 사전 검토.

## AI 협업 실무 규율
- `str_replace`의 old_string은 **짧고 유일하게** 잡는다. 제네릭·셰이더의 꺾쇠 `< >`가 많은 코드는 컨텍스트가 오염되기 쉬우니 범위를 좁힌다.
- MCP(Unity/Blender)는 **작은 단위**로 끊어 실행한다. **파괴적 작업**(파일/오브젝트 삭제, 모디파이어 적용, 씬 대량 변경)은 실행 전 확인을 받는다.
- 컨텍스트가 **50~60%**에 이르면 정리(`/compact`)하고, 중요한 진행 상태는 `PROGRESS.md`에 남긴다.
- Blender MCP: 첫 명령이 누락될 수 있으니 확인하고, 큰 작업 전 저장한다. 샌드박스가 아니므로 신중히.

- 착호 병과 채택 여부.
- 마물 이중 명칭(관보식/민간) 채택 여부.
- 황경·조정 톤 방향(신(信) 변질 테마, 인정·파루·순라 연출 앵커) — 제안 단계.
- 무학대사 정체.
- 황경 보스 「개천 이무기」 — [제안] 상태.

- 마석을 화폐로 쓰기 / 작도를 추상 도형으로 되돌리기.
